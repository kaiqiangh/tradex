# TradeX Prototype Coverage Matrix — v1.0 RevC

**Status:** RevC aligned baseline  
**PRD:** `TradeX_PRD_v1.0_RevC.md`  
**UI Spec:** `TradeX_UI_Prototype_Spec_v1.0_RevC.md`  
**Prototype:** `../prototype/index.html + styles.css + app.js`  

This matrix distinguishes UI/state semantics that a standalone prototype can prove from behaviors that require the real Codex runtime, broker adapters, privileged gateway, storage, or reconciliation implementation. A fixture is never presented as a completed broker integration.

## 1. Revision C critical alignment

| Topic | RevC decision | Prototype evidence |
|---|---|---|
| State model | Agent Mode = Ask / Research / Backtest / Trade; Execution Context is independent and account/environment-derived. | app.js mode cycle + executionContext(); UI Spec §3–4 |
| Live authority | Arming is account-scoped; switching accounts does not inherit arming; Disable All clears every armed account. | armedAccounts Set; Account Health + top banner |
| LLM routing | CLIProxyAPI + ChatGPT OAuth and DeepSeek are explicit; automatic cross-provider fallback is OFF by default. | Onboarding Model step; Settings → Providers & Models |
| Proposal/approval | OrderDraft is editable; generated OrderProposal is immutable and carries proposal ID/hash/policy version. | Live approval + order audit |
| Reservation | APPROVED → RESERVED → SUBMITTING and reservation conflict are explicit. | Order activity + reservation conflict fixture |
| Ambiguous submission | UNKNOWN_RECONCILING uses evidence-based Manual Resolution; no blind reservation-release shortcut. | Manual Resolution modal |
| Market provenance | Source/provider timestamp/TradeX timestamp/venue/entitlement/age/freshness appear in live approval. | Market snapshot provenance card |
| Storage | SQLite = transactional/domain; DuckDB = MVP 1m+ OHLCV/analytics/backtest; Filesystem = artifacts; Parquet optional Phase 2+. | Settings → Data & Storage |
| Market-data lifecycle | No persistent Warm-tier claim in MVP; watchlists use on-demand/coarse refresh. | Watchlists + PRD §32 |
| Prototype scope | No cloud Share link; workspace portability is Export / Workspace Import-Restore. | Top bar + Data & Storage |

## 5. Intentional prototype limitations

- No real Codex App Server, CLIProxyAPI, broker/exchange, or market-data backend is contacted.
- No real order/cancel, OAuth, keychain, SQLite/DuckDB write, or workspace archive I/O occurs.
- P2 Futures, A-share integration, and additional providers are outside the RevC v1.0 prototype scope.
- Browser-level visual-regression and screen-reader QA remain a separate pre-implementation gate; source includes `focus-visible`, dialog ARIA, `aria-live`, and `prefers-reduced-motion` baselines.

These are explicit prototype boundaries, not unresolved PRD ↔ prototype mismatches.
