Status: **IMPLEMENTATION_IN_PROGRESS**, 2026-10-01. Start reference: `dev@dc4c350397bbe500983b47fdfd5d1c3af2f20455`. [中文](s28-alpaca-production-quotes_zh.md). ## Problem Statement

The ordinary application cannot consume the already selected OD-001 source. Its credentialed probe always returns BLOCKED_EXTERNAL, no source configuration can be saved, and ordinary market detail returns no quote even when a source entry is AVAILABLE. Market Explorer's Hot detail has no production subscription. The completed synthetic approval chain therefore cannot establish production quote readiness. An Alpaca Paper broker link does not establish feed entitlement or coverage.

## Solution

Deliver one complete source-configuration-to-quote slice: explicitly configure independently scoped Alpaca market-data access, verify the selected feed through the provider, fetch on demand for Census/Warm and maintain an active Hot subscription, publish authoritative exact quotes with their provenance, and consume those same observations through existing market and approval/risk surfaces. Source access never grants financial authority. Other S28 prerequisites remain separately visible and unresolved.

## Implementation Decisions

- Reuse the existing secure vault, source catalog, versioned command/job pattern, provider scheduling, market projections, TimeService, approval digests and UI surfaces. The new durable source configuration owns a generation/version and contains only metadata and an opaque credential reference. Secrets stay in the native vault. Explicit reuse does not duplicate ownership of an account's vault item.
- Add typed configure/disconnect lifecycle and sanitized source connection/verification projections. Configure has explicit credential-reference selection or native dedicated-credential setup; the ordinary renderer and Agent cannot submit a market observation, entitlement attestation or arbitrary provider URL.
- Fixed Alpaca data HTTPS/WSS endpoints and exact supported paths only, redirects disabled, explicit feed and canonical symbol mapping, bounded bodies/frames/timeouts, read-only GET and subscription traffic. No broker POST/DELETE or privileged Gateway action belongs to this adapter.
- Provider-confirmed access to the explicitly requested feed establishes that feed's technical availability only. Freshness, coverage, licence/retention restrictions and financial readiness remain distinct. IEX is single-venue realtime; delayed SIP remains delayed; SIP permission failure never changes feed implicitly. No plan purchase, agreement acceptance or permission expansion is automated.
- Keep quote feed/coverage and bid/ask exchange evidence distinct from listing/execution venue. The authoritative coverage-aware eligibility contract must be documented in both languages before implementation; do not relabel IEX as XNAS or a consolidated NBBO as a single-venue order book. Unknown coverage/venue mapping stays unavailable for execution.
- Parse decimal tokens without floating-point conversion. Determine size units for the exact HTTP/stream endpoint from current authoritative evidence. The generic stream page still describes round lots, but the later official CTA/UTP changelog states that quote sizes became share counts from2025-11-03. For current SIP CTA/UTP quotes, preserve those exact share counts as BASE depth without multiplying by100. This is a feed/date-specific contract; do not extrapolate it to IEX or historical data. BASE depth for any other supported path requires verified applicable units/conversion; unresolved mappings remain explicitly unavailable rather than fabricated depth. Quote prices may still be presented honestly. Financial-positive acceptance cannot be claimed from unverified depth.
- Validate provider symbol, requested feed, supported quote conditions, timestamp precision, source/config generation and instrument identity. Use current TimeService to age quotes on every read and approval phase. Changed prices/depth/provenance/source generation invalidate existing consent through the shared quote material, without weakening S28's exact slippage comparison.
- On-demand Census/Warm fetches and one active Hot stream per configured workspace/source respect quotas and provider connection limits; subscriptions cover requested supported symbols only. Hot navigation/reconnect uses generations so late frames cannot replace another instrument's/current credentials' observations. Reconnect is bounded, and backpressure/cooldown marks observations non-current.
- Persist configuration/audit metadata in SQLite; quotes and Hot buffers remain bounded memory. Reopen clears live verification/quote freshness and never restores an approval or ARMED state. Source disconnect clears its observations and subscriptions, preserving unrelated account/vault ownership.
- Preserve the existing canonical provider/receipt timestamp binding in risk/review digests. Reading an already accepted quote returns that same observation and its original receipt time; a repeated identical provider event does not refresh its freshness. A new provider timestamp, changed quote material or source/connection generation is new evidence and invalidates old consent. Snapshot identity includes those authoritative dimensions; a view collection time is not a provider event.
- WebSocket upgrade/connected is not authenticated access. Require the authenticated acknowledgement and the requested-symbol subscription acknowledgement before Hot is current. Handle HTTP status codes separately from stream protocol errors: stream402/404 are authentication failure/timeout,405 symbol limit,406 connection limit,407 slow client and409 insufficient subscription; stream403 means already authenticated, not HTTP Forbidden. Never infer entitlement from the public test stream or FAKEPACA.
- Maintain a single managed connection for the active workspace/source in the native process, with bounded auth/subscription deadlines, frames and buffer. Connection-limit errors from other applications remain visible and require cooldown/manual remediation; do not stop another application's connection or open concurrent retries. No wildcard symbol subscription is part of this slice.
- Hot updates use typed ephemeral subscription generations/sequences; do not fabricate a SQLite domain sequence or persist quote ticks to make replay appear supported. On reconnect, mark old observations stale and require a fresh authenticated/subscribed stream plus actual provider observations. Late/older responses cannot replace current evidence; conflicting unordered observations remain unavailable rather than guessed current.
- Synchronize shared IPC generation, English/Chinese Backend/Frontend/UI contracts, requirement evidence and operational documentation. Do not mark FR-016/AC-010 or the parent VERIFIED on this local slice.
