## Delivered correction

Live Market DAY requires a positive exact-decimal `maximumSpend` in the immutable Proposal. The shared Trading 212 request builder previously rejected that field even for a valid consumed Live intent. It now validates and retains the local financial bound while serializing only the official ticker, signed BASE quantity and `extendedHours: false`. Demo and Limit rejection rules stay unchanged. The approval surface explains that this local authorization/reservation amount is not a broker-enforced market price or value ceiling. Paired Backend §41.36, Frontend §13.22 and UI §14.2 document this boundary.

The official [Trading 212 API](https://docs.trading212.com/api) and OpenAPI were checked on 2026-09-30; OpenAPI SHA-256 `a272f70a713fa9f2f906e9b4be12136c9d5d63d7f9f48562e939aa35c4fc041d`. No `maximumSpend` request field is defined. Sell is signed negative; Limit uses DAY/GOOD_TILL_CANCEL; acknowledgement is distinct from fill or completed cancellation.
