# S29.9 — 为精确金额 Binance Spot Live PLACE 履行「费用证据与真正所需执行 FX」拥有方资格

父项：[验证 Binance Spot Live 可信执行](https://github.com/kaiqiangh/tradex/issues/121)。实现/复审起始基线 `dev@1f8e231de3fe67aec16db1ae7392f34981617330`。[English](s29-fee-and-required-fx-spec.md)。仅规划；尚未实施与验收。

## 问题陈述

面向普通 Binance Spot Live 账户的拥有方 Live PLACE 路径现已依据交易所自己声明的容量与时段额度证据作出准入判定（S29.8），并且已经携带 S28 #120 的只读货币路径与非合格汇率，以及盘后结算费用。但用户在授权一笔精确金额 Spot Live 订单前必须判断的两个事实，仍不在拥有方门禁的判定之中。

其一，没有任何拥有方路径陈述交易所为这一精确账户、标的与方向声明的费用，或该费用被计入哪一种资产；产品唯一展示过的费用是 `LiveOrderSettlement.fees`，它只在成交之后才存在。因此用户授权的是一笔费用未言明的支出，而复核实际上默认费用以计价资产计。其二，已交付的 FX 上下文刻意是只读且组合维度的：它列出每个账户的余额、持仓与开放订单币种，以及该 Proposal 的策略与出资路径，并永久让 `CURRENCY_CONVERSION` 保持 `UNAVAILABLE / CURRENCY_CONVERSION_UNAVAILABLE`。没有任何东西把它收窄到本次下单真正需要的换算——把精确预期支出对照声明的名义金额与授权上限——也没有任何东西为执行陈述这些换算的方向、质量、时效或成本。读取任一页面都不改变拥有方门禁的判定：审批复核仍合格、Prepare 仍继续，而必需的换算缺失、某个无关余额的币种看起来像阻塞、费用币种未言明。已交付的证据沦为装饰而非权威，父项故事 14、15、23 在拥有方路径上仍未回答。

## 解决方案

让现有面向普通 Binance Spot Live 账户的拥有方 Live PLACE 路径，消费一份审批绑定的**费用陈述**与一份审批绑定的**真正所需执行 FX 陈述**，二者均由精确的不可变意图与已交付的接缝推导，并遵循与已交付切片相同的精确性与失败关闭纪律。对一笔已复核的精确金额意图，用户看到交易所声明的费用及其确切计入资产，以及本次下单真正需要的每一项换算——各带其方向、质量、时效与保守成本——或者阻止它的唯一类型化阻塞。仅当两份陈述当前且完整可用时，Prepare 才原子地消费审批并预留容量；否则以已交付的 `RISK_EVIDENCE_UNAVAILABLE` 语义拒绝且不创建任何预留。此处不授予 Arm、consent、派发或任何新的执行权，且盘后结算费用契约、ACK/fill/CANCEL 分离以及「费用恰好一次结算」规则原样保留、不被更改。

## 用户故事

1. 作为用户，我希望交易所声明的费用及其确切计入资产保持原始 BASE/QUOTE 与费用币种，从而 USDT 绝不被人当作 USD，且计入第三方资产的费用绝不被展示为计价资产。
2. 作为用户，我希望预期费用以声明的费用币种、用精确十进制与保守的声明费率推导，从而任何舍入都不会向我展示比交易所实际收取更小的费用。
3. 作为用户，我希望只有本次下单真正需要的换算被检查，从而必需的换算绝不跳过，而来自其他账户的无关余额、持仓或开放订单绝不凭空造出换算。
4. 作为用户，我希望每一项真正所需的换算都带其方向、提供方质量、提供方时间戳、首次接收与保守成本，从而我能看到执行实际花费多少，而不只是某处存在一个汇率。
5. 作为用户，我希望同币种路径被当作精确恒等，从而在无需换算时绝不虚构换算、汇率或平价。
6. 作为用户，我希望费用陈述与所需 FX 陈述绑定到精确的不可变 Proposal、账户、标的、规则材料与来源代际，从而他人的证据无法为我的意图定性。
7. 作为用户，我希望缺失、失败、过期、退役或版本变更的费用或汇率观测以唯一类型化阻塞使陈述关闭失败，从而昨天的费用或汇率无法授权今天的精确支出。
8. 作为用户，我希望不支持或方向不成立的所需路径保持明确的不支持，而不是被平价或跨币种桥接替代，从而 USDT 绝不被人当作 USD、EURUSD 绝不从 USDEUR 推断。
9. 作为用户，我希望精确预期支出与声明的授权上限以各自确切的单位展示，从而交易所原生的 QUOTE 金额与工作区基准货币上限绝不被混为一谈。
10. 作为用户，我希望 Prepare 原子地消费审批、预留容量，并在任一声明不当前时拒绝整次尝试，从而我绝不会为一笔费用或必需换算未言明的精确支出持有预留。
11. 作为用户，我希望 ACK、fill 与 CANCEL 路径保持分离、结算费用恰好应用一次，从而盘前费用陈述是诚实的证据，绝不成为第二次扣费或虚构的释放。
12. 作为用户，我希望捕获与 pre-arm 复核展示当时真正被依赖的费用与所需 FX 陈述且不续期，从而使已保存的评估保持诚实。
13. 作为用户，我希望随后的 get、refresh 或重开无法为已捕获的费用或 FX 陈述续期，从而使历史不会变成新鲜授权。
14. 作为用户，我希望费用币种、所需方向与绑定阻塞原因与数字一同给出，从而我可以指出该修什么而不是靠猜。
15. 作为用户，我希望绝不接受渲染器提供的金额、数量、汇率或费用，从而交易所声明的数字始终是我费用与换算证据的唯一来源。
16. 作为用户，我希望键盘与 1280/768/390 复核中费用、换算成本与唯一阻塞原因与金额同样醒目，从而使金融同意保持审慎。
17. 作为用户，我希望即使所有费用与汇率都当前，精确金额 Spot Live 订单仍保持执行未获资格，从而任何费用或汇率陈述都不被呈现为成交承诺、准入保证或即时认证 preflight 的替代。
18. 作为复核者，我希望有真实的公开 RED 先于 GREEN、精确来源检查、普通构建与独立串行 Standards → Spec 证据，从而任何标签或仅 fixture 的投影都不能确立本切片。

## 实现决策

- 仅对普通 Binance Spot Live 账户、且仅对精确金额 Market/Limit 意图边界，扩展既有拥有方 Live PLACE 路径（风险判定 → 不可变审批复核 → Prepare → 已认证子 Gateway）。不引入并行权威模型、不新增第二套费用或 FX 投影、不新增第二套结算路径、不新增账户、不新增已保存来源或来源选择命令，也不接受渲染器提供的金额、数量、汇率或费用。本切片不进行任何提供方写操作、不下探针订单、不 Arm、不 consent、不派发。
- **消费而非重造。** 费用与所需 FX 陈述均由已交付接缝推导：S09 的账户币种/FX 归一化与 FX/稳定币出处及其脱锚/质量处理（`FR-014`、`FR-065`、`FR-079`、`AC-053`、`AC-066`、`DATA-004`、`DATA-008`，状态 `IMPLEMENTED_UNVERIFIED`）；S28 #120 已交付的 `financial_sources::fx_requirements`、`financial_sources::review_context`、`FxRequirements`/`FxReviewEvidence` 形状与 `RiskDecisionInputKind::CurrencyRates` 审批绑定输入，以及已交付的 `CurrencyRates`/`CURRENCY_CONVERSION_UNAVAILABLE` 风险行为；由 S29.2 规则来源与 S29.5 容量切片各自的精确账户认证读取已经取得的交易所声明佣金证据（二者都读取账户响应并把其 `commissionRates` 作为原始十进制校验，但刻意不投影它们）；已交付的 `LiveOrderSettlement.fees`/`feesComplete` 与 `LiveOrderTradeFact.fees` 盘后契约；以及 S29.4/S29.5/S29.6/S29.7/S29.8 的规则材料、来源代际、容量、时段、价格区间与拥有方准入接缝及其绑定身份。本切片不重读任何已交付切片已取得的证据，也不重塑任何已交付投影。
- **费用陈述。** 拥有方路径为精确的不可变意图推导一份有界费用陈述，来源是交易所声明的佣金证据与交易所声明的费用计入资产，在既有拥有的普通 Binance Live 连接上按既有有界读取纪律读取：仅固定普通公开主机，不允许重定向、不允许 Testnet 或区域主机回退、不允许访问绕过；沿用既有共享 IP/UID 预算、每响应 512 KiB 上限、30 秒截止与 12 秒完成裕量；不在 vault 或网络 I/O 期间持有 Control Plane 锁；不新增已保存来源或凭证。凡交易所声明的佣金证据已由某个已交付读取携带，则消费该证据而非再次获取。声明的 maker 与 taker 费率按原值作为精确十进制上报，**预期费用**用**保守的声明费率**（绝不取二者中较小者）推导，从而任何舍入或费率基准选择都不会展示比交易所声明更小的费用。**费用币种**即交易所声明的费用计入资产，按原值上报；当交易所并未真正声明它时，费用币种为 `UNKNOWN`，陈述关闭失败，而绝不默认为计价资产、基础资产或 USD。
- **真正所需执行 FX。** 所需 FX 陈述由同一套已交付路径推导收窄而来，仅保留本次下单为精确选定账户真正需要的用途：意图路径（精确预期支出/收入币种到工作区基准货币）以及（仅买单）意图出资路径（出资单位到工作区基准货币），且二者均须为非恒等路径。任何账户（含选定账户）的账户级、余额级、持仓级与开放订单级路径属于组合的职责，绝不是本下单的门禁。仅当该精确提供方币对与方向的已交付汇率存在于一份当前、未过期、且绑定到同一账户、来源、材料代际与需求材料的观测中，其提供方时间戳与首次接收处于执行时效窗口内，且该路径的保守成本可由其原始 bid/ask 精确推导时，该路径才 `QUALIFIED`；否则该路径为 `UNQUALIFIED`、`UNSUPPORTED_ROUTE` 或不可用，陈述关闭失败。两币种相等的路径为精确恒等，无需汇率。
- **USDT ≠ USD，禁止平价。** 每个币种 token 均按交易所与已交付接缝声明原值保留。USDT、USD、USDC 与工作区基准货币彼此不同；绝不引入任何隐式平价、倒数或跨币种桥接，EURUSD 与 USDEUR 始终是彼此独立的定向观测，绝不互相推断。已交付有界生产者无法支持的所需路径（例如 USDT 到 EUR）保持明确的不支持、其换算保持不可用；绝不改写为受支持路径。
- **精确性。** 所有算术只用 `provider_io::decimal`、`provider_io::decimal_cmp` 与 `provider_io::decimal_subtract`（以及既有精确乘法辅助）。禁止 `f64`、禁止浮点、禁止舍入，也禁止以任何可能使其小于交易所自身数字的方式对费用或换算后金额做舍入。精确预期支出即意图自身以其自身 QUOTE 单位计的名义金额；工作区基准货币数字仅当对应所需换算真正合格时才存在。
- **类型化陈述与类型化阻塞。** 费用/所需 FX 陈述携带精确的绑定身份与显式状态枚举——`SPOT_FEE_FX_QUALIFIED`、`SPOT_FEE_FX_EVIDENCE_MISMATCH`、`SPOT_FEE_EVIDENCE_UNAVAILABLE`、`SPOT_FEE_CURRENCY_UNKNOWN`、`SPOT_FEE_RATE_UNSUPPORTED`、`SPOT_REQUIRED_FX_EVIDENCE_UNAVAILABLE`、`SPOT_REQUIRED_FX_UNQUALIFIED`、`SPOT_REQUIRED_FX_UNSUPPORTED_ROUTE`——并携带实际所用声明费率基准、声明的费用币种及其声明出处、以该币种计的精确预期费用、以 QUOTE 计的精确预期支出、工作区基准货币、仅当所需换算合格时的工作区基准预期支出与费用、至多两条有界所需路径条目（用途、from/to 币种、方向、提供方币对、质量、提供方时间戳、首次接收、保守成本）、已载入的出处限制，以及两个绑定证据版本摘要。唯一绑定阻塞是类型化原因，绝非自由文本。已消费切片的固定出处标签按原值载入，绝不自我升级为第二重隐藏门禁；致命集合恰为「未知或不完整的费用/路径证据」。
- **拥有方消费。** 非 `QUALIFIED` 的费用/FX 陈述向不可变审批复核贡献恰好一个类型化阻塞，使该复核不合格、既有 Prepare 资格路径以 `RISK_EVIDENCE_UNAVAILABLE` 拒绝且不创建预留、不产生部分状态；不新增第二套发散的判费用或判 FX 检查。既有 `CURRENCY_CONVERSION` 检查仅对真正需要且真正合格的路径变为 `PASS`，否则保持其已交付的 `UNAVAILABLE / CURRENCY_CONVERSION_UNAVAILABLE` 含义。仅同币种、无需换算的意图仍需要费用陈述。拥有方门禁始终针对新推导的陈述评估，从而一项此后已过期的陈述绝不可能从已复核的决策中重放；对费用或汇率证据的真实变更会改变复核摘要并使复核不合格，因此再次准入需要一次新复核的审批。
- **结算不变。** 盘前费用陈述仅为证据。已交付的 ACK / fill / CANCEL 分离、费用恰好一次结算（`LiveOrderSettlement.fees` / `feesComplete`、`LiveOrderTradeFact.fees`）、「仅为实际释放的容量释放预留」规则、未知 PLACE 对账，以及「提供方读取绝不释放本地预留」规则，均原样继承，本切片不得削弱它们。
- **执行未获资格。** 即使所有数字都当前，该陈述也绝不授予 Arm、consent、派发或任何新权限。它不是成交承诺、不是交易所后续 taker 阶段的费用或换算保证，也不能替代权利、报价、权限、健康、出资、动态准入、Arm、consent、Prepare、Gateway 或即时认证 preflight。
- **契约与配对。** 生成的线缆契约必须恰好容纳本契约实际产出的值：两个绑定证据版本按 `sha256:` 值的 71 个字符声明（与 `proposal_hash` 一致），因为 React 在任何组件读取之前先用生成的校验器解码每个响应。配对的中英金融/线缆/证据契约保持同步。原型代码保持不变。
- **AC-035 处置。** 本切片是精确金额普通 Binance Spot Live 路径上 **`AC-035` 的「费用估算」与「预期/最大授权支出」部分的拥有方归属**：精确预期支出与声明的授权上限以各自确切单位展示，费用估算以声明的费用币种展示，并在所需换算真正合格时同时给出工作区基准等价金额。**`AC-035` 的 bid/ask/spread/quote-age 部分仍归报价/深度拥有方切片**（S29.3 #124 及已交付的报价时效生产者），不在此声明。**可变金额的市场订单路径不属于本切片**，仍为独立拥有方工作，因为精确金额意图才是「预先授权的最大支出」有意义之处。因此 `AC-035` 整体保持 `NOT_STARTED` 且**不**声明关闭；其需求矩阵行应仅为费用与支出部分加入本切片。本切片不修改任何其他需求行。
- **门禁保持 OPEN。** 父项 #121、map 门禁 #1、S28 门禁、S17、物理 S27 休眠豁免、S27/S28 金融门禁与 `dev`→`main` 合并保持 OPEN，仍在进行中的 S29.3/S29.5 生产者验收不变。本切片不声明其中任何一项关闭。

## 测试决策
