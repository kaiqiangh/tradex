## Problem Statement

Trade names missing dynamic order-count and position obligations but cannot show a current complete bounded account inventory behind them. Visible orders for one symbol, old account balances or rate-limit counters cannot establish exchange-wide open-order capacity or the base asset exposure of an immutable Proposal. Users need observed inputs, their coverage and the remaining qualification gap before reviewing consent.

## Solution

Provide one complete read-only vertical slice: select an existing ordinary Binance Live BTC/USDT or ETH/USDT Proposal, explicitly collect only its required exact-account capacity inputs through fixed authenticated GETs, and show bounded typed inventory/count/position observations with original provenance and unresolved completeness in Trade/current and captured review. This source prerequisite does not itself qualify dynamic financial rules, funding, Arm, consent or dispatch. A later owning evaluator/preflight must establish applicable execution qualifications; no positive authority seed is introduced here.

## User Stories

1. As a user, I want capacity observations bound to my saved immutable Proposal and exact account, so that another account's inventory cannot qualify my intent.
2. As a user, I want required inputs derived from actual active scoped rules, so that unrelated account reads are not made.
3. As a user, I want one-symbol and exchange-wide counts kept distinct, so that unseen foreign-symbol orders are not dropped.
4. As a user, I want interval unfilled-order counters kept separate from open-order filter counts, so that an unrelated API counter cannot replace inventory.
5. As a user, I want observed ordinary, algorithmic, iceberg and list coverage explained, so that unknown classifications cannot be silently counted as zero.
6. As a user, I want list identity and missing pending legs represented, so that advanced orders outside TradeX cannot hide reserved capacity.
7. As a user, I want original free and locked BASE balances separated from open BUY exposure, so that holdings and pending purchases are not confused.
8. As a user, I want original quantity and executed quantity preserved where relevant, so that partial fills cannot be silently converted into guessed capacity.
9. As a user, I want foreign-symbol/asset uncertainty visible, so that a ticker prefix cannot invent authoritative asset membership.
10. As a user, I want source coverage and response bounds shown, so that a truncated, duplicate or malformed inventory is not a complete account observation.
11. As a user, I want provider update times separated from local collection receipts, so that last state change is not impersonated as snapshot freshness.
12. As a user, I want separate HTTP observations labelled as non-atomic, so that receipt proximity does not manufacture a provider snapshot guarantee.
13. As a user, I want explicit refresh and sanitized recovery, so that missing/auth/quota/deadline failures retire current inputs without losing the explanation.
14. As a user, I want source/account/credential/Proposal/session/time changes and late responses rejected, so that stale reads cannot attach to new intent.
15. As a user, I want captured review outcomes and digests retained without raw private account inventory, so that history does not become a refreshed current read.
16. As a user, I want units, unresolved qualification and independent financial blockers visible by keyboard and at narrow widths, so that observing capacity never implies approval.
17. As a reviewer, I want genuine public RED/GREEN and exact-byte local/build/UI/serial-review evidence, so that hidden snapshot seeds cannot close this source prerequisite or the full parent.

## Implementation Decisions

- Retain the confirmed single-ticket public React → actual typed Rust Control Plane → owned temporary SQLite/outbox → external fake vault/HTTP/WS seam. Reuse immutable Proposal, exact selected account/key ownership, current rule metadata, trusted clock, provider read scheduler/budgets and current/captured Trade explanations. No new account configuration, renderer credential/host/symbol/count/balance input, background scan or standalone financial authority model.
- Add trusted `trade.spot_capacity.get` and explicit CAS `trade.spot_capacity.refresh` operations identifying only workspace/stored Proposal/current state. Backend derives actual required purpose, exact account/remote UID/credential version, canonical BTC/ETH/USDT, actual rule scopes/material and workspace/source/policy/session/time bindings. Collecting no required purpose must perform no unnecessary private read. Bound concurrent ownership/slots/generation/deadline and reject foreign or changed state before publication.
- Use only fixed ordinary Binance authenticated USER_DATA GET routes and existing signed/vault/zeroization boundary. Account information supplies exact identity and original relevant BASE free/locked fields. Full-account open orders are necessary when exchange-wide or shared-asset coverage is required; a symbol-only subset is never complete for these purposes. Open order-list inventory is collected only for actual list/leg completeness needs. Default proposed route costs are clock2, account20, full openOrders80 and openOrderList6, rechecked against official contracts before implementation. Charge genuine signed-account UID/IP budgets, with no quota reset or public UID fiction; defer on shared cooldown, preserve remaining deadline and never hold CP lock across vault/network I/O.
- Keep interval unfilled-order counters, request-rate/ORDERS limits, open-order filter inventory and local reservations as distinct concepts. The rateLimit/order endpoint is not an open-order inventory substitute; do not call it for this source slice. No order test/probe, PLACE/CANCEL/amend/list creation, listen-key mutation or financial authorization occurs.
- Parse bounded original JSON types, duplicate fields, UID/symbol/order/list identities, original exact decimals, statuses/types/side/iceberg observations and timestamps before projection. Proposed hard limits:512KiB per response,1000 account open-order rows,256 open-list rows and1024 balance rows; bounds are validation limits, never truncation. Reject oversized/ambiguous/duplicate/non-open/malformed collections or preserve a specific incomplete status; never drop rows to report complete coverage. Preserve int64 identities/counts as exact strings across IPC. Unknown active fields/statuses/classifications remain unresolved, not zero or ordinary by default.
- Project bounded coverage/counts and selected BASE balance/exposure observations, not raw private inventory. Clearly distinguish exact observed values from any conservative bound and unavailable asset attribution. No inferred foreign-symbol BASE mapping, USDT/USD parity, assumed advanced-list leg state or guessed remaining quantity. A partly filled/open BUY ambiguity must remain explicit until an owning execution contract resolves its semantics. Do not silently certify MAX_POSITION from selected-symbol BUY orders when other asset exposure may exist.
- A full returned array establishes only completeness of that particular bounded response under its documented endpoint contract. Separate account/orders/lists reads have no documented common atomic watermark here; expose read windows, original account/order/list update times where supplied, absent aggregate provider observation time and quality READ_ONLY_SPOT_CAPACITY. Provider clock samples remain clock observations. Never relabel a last update as current provider snapshot time or claim complete atomic capacity. Contradictory list/leg/identity/time observations remain unresolved.
- Fresh get/cached history never renews a collection receipt. An actual explicitly authenticated re-read creates a separately identified collection observation; keep that observation's original first receipts and material digest. Expiry, account/credential/source/rule/market/policy/Proposal/workspace/session/clock changes retire current eligibility, and failed refresh clears current inputs while retaining only sanitized last-observation explanations. Reopen restores configuration/history only and performs no implicit private collection.
- Owning dynamic rule evaluation remains UNAVAILABLE/DYNAMIC_INPUTS_NOT_EXECUTION_QUALIFIED in this source slice, including when complete bounded observations arrive. Collecting inputs cannot upgrade MARKET_DATA_USE/data rights, key permissions/health, quote/liquidity, fees/FX, funding/reservations, Arm, consent or immediate Gateway preflight. Preserve exact independent CANCEL/reconciliation paths. A later synchronized contract must distinguish applicable plain-intent capacities and authenticated execution qualification; do not pre-solve it with a hidden positive snapshot.
- Current and captured UI expose identity, actual required purpose, units, exact versus incomplete coverage/classification, non-atomic quality, original times versus receipts, age/failure and explicit read-only recovery. Captured risk/review history stores only approved bounded aggregate observations/digests, not raw account/balance/order/list responses or runtime caches; it has no refresh/polling controller. Paired English/Chinese financial, IPC and interaction contracts must be synchronized during implementation.
