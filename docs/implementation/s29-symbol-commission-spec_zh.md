# S29.10 — 精确标的佣金来源与条件扣费证据

[English](s29-symbol-commission-spec.md)。[父项](https://github.com/kaiqiangh/tradex/issues/121)、[规范门禁](https://github.com/kaiqiangh/tradex/issues/132)、[单一实现票](https://github.com/kaiqiangh/tradex/issues/133)。规划已发布，实现NOT_STARTED；原生121→132→133，已完成依赖123/131，0开放阻塞。

## 问题陈述

当前 Binance Spot Live 复核只报告账户级佣金费率及 UNKNOWN 费用币种，缺少精确标的的税费、特殊佣金和折扣条件。用户无法查看完整标的佣金声明，也无法区分收到资产扣费与有条件的 BNB 支付。这阻碍后续拥有方费用资格；已交付 S29.9 陈述不能冒充该资格。

## 方案

为已保存 Proposal 的精确普通 Binance 账户及规范 Spot 标的提供一次显式只读采集。展示完整声明的佣金类别、折扣条件、原始收讫及条件扣费分支。有效来源观察是有用证据，不是审批或成交时费用承诺。来源可以有效，而拥有方费用/执行 FX 复核仍不可用。完整费用金额边界与真正所需 USDT 执行 FX 仍为后续拥有方必需工作。

## 用户故事

1. 作为用户，我希望读取精确账户和标的的佣金条款，以免通用账户费率冒充完整标的费用。
2. 作为用户，我希望查看 standard、tax、special 三类各自 maker/taker/buyer/seller 费率，以免遗漏实际适用类别或方向。
3. 作为用户，我希望看到原始十进制字符串和声明单位，以免显示舍入缩小费用或改变意义。
4. 作为用户，我希望看到账户/标的折扣开关、资产和原始折扣值，以便了解设置而不把它当作保证支付方式。
5. 作为用户，我希望理解 BUY 收到 BASE、SELL 收到 QUOTE 的扣费分支，以免全部费用都被赋为 USDT 或报价币种。
6. 作为用户，我希望 BNB 支付明确取决于足够余额和换算证据，以免仅凭开关决定费用资产。
7. 作为用户，我希望缺失及未知活动条款标为未解决，以免被默认为零。
8. 作为用户，我希望通过已有连接显式读取，以免查看保存的评估触发认证采集。
9. 作为用户，我希望 Proposal hash、来源代际及账户身份绑定采集，以便编辑或连接变化使证据退役。
10. 作为用户，我希望看到原始本地开始/首次收讫及缺失的提供方时间，以免数据库响应冒充当前执行证据。
11. 作为用户，我希望失败刷新、过期及迟到结果保持不可用，以免旧成功修复变化的输入。
12. 作为用户，我希望当前、捕获及 pre-arm 展示实际依赖的同一条款，以便历史在再次采集或重开后仍不可变。
13. 作为用户，我希望缺失或变化的条款改变复核绑定，以免后续审批假定旧采集仍可用。
14. 作为用户，我希望读取有界且认证/限流错误可理解，以免重复点击造成无控请求。
15. 作为用户，我希望来源成功与费用/FX 资格区分，以免观察条款授权 Arm、审批、预留或发送订单。
16. 作为用户，我希望键盘和窄屏可用，以便长费率、hash 及扣费条件仍可读。

## 实现决策

- 复用已确认公开 React → 类型化 Rust Control Plane → 临时 SQLite/outbox → 外部假 vault/HTTP 接缝。没有 renderer 费率/费用/资产/资格或金融权威 setter。相同接缝和单票串行粒度已有用户持续授权，不重复询问。
- 复用已有 Binance Spot Live 凭据及固定普通主机。一次显式 Proposal 采集先通过签名账户信息验证 UID，再为精确规范 symbol 签名读取 `GET /api/v3/account/commission`。无 test-order POST、账户设置变化、新保存主机/来源或凭据。为提供方时间及每个声明请求保留共享预算，commission weight20。遵循已有 deadline、当前作业、重试/退避及凭据保护。
- 来源拥有有界类型化观察，不替代 capacity 或账户费率投影。绑定 workspace、账户/远端身份、凭据/连接代际、Proposal/hash、instrument/BASE/QUOTE 和当前 rule-source/material。当前版本 token 保护刷新；过期作业不能发布到变化身份。未知或矛盾身份失败关闭。
- 保留十二个费率原串及两个折扣开关、折扣资产和值。验证有界精确非负十进制、重复/缺失字段、未知活动 extension 及精确 symbol。未知活动费用语义保留为未解决，不能视为零或完整。
- 来源状态与执行资格分离。commission API 数据源为数据库，响应没有提供观察时间。保留原始本地开始/收讫、单调时钟过期及 material version，不制造提供方时间，不让缓存 get/capture 更新鲜度。两个私有读取非原子。
- 按 BUY BASE / SELL QUOTE 解释官方收到资产扣费分支。折扣可能生效时，将 BNB 列为有条件分支并同时展示收到资产回退；账户 free 余额或开关本身都不能证明未来成交扣费资产。余额和换算在拥有方证据建立前保持未获资格。
- 本票不计算或授予总费用/折扣 BNB 金额资格。官方示例使用不同折扣数值；原样保留，并在后续算术前固定其解释。账户级 max(maker,taker) 仍只是比较基准。SELL limit quantity×limit price 在价格改善下不是保证的最大所得/费用；后续金额上界必须考虑实际允许执行区间。
- 将来源观察/版本绑定当前 risk/approval review 及捕获证据。真实费率/折扣/来源变化改变复核摘要，已有拥有方门禁继续阻止完整金融资格。独立来源 PASS 不能升级为 `SPOT_FEE_FX_QUALIFIED` 或权限。
- 保留 S29.9 来源/拒绝语义及其历史捕获。追加来源显示，说明来源边界及两个缺失的拥有方金融依赖。同步英中契约、证据及追溯。AC-035 在完整验收取得前保持 NOT_STARTED。

## 测试决策

使用最高已确认产品接缝。外部 fixture 改变 HTTP/vault 响应；Control Plane 接收正常类型命令并自行管理存储。实现前取得真实公开 RED，覆盖完整正常条款、缺失/不完整/重复字段、symbol/UID 错配、未知活动义务、折扣开/关、过期、Proposal/来源/连接变化、迟到结果、提供方/认证/限流失败及不变捕获/重开。已有 capacity/fee 与来源生命周期测试为先例。观察精确 GET 方法/symbol/签名预算，确认无 POST/Arm/consent/预留/派发。实际 React 当前/捕获/pre-arm 与键盘1280/768/390 保持完整披露，无溢出/控制台错误。普通/schema/受影响/完整检查、普通桌面构建/Gateway pin 及独立 Standards 后 Spec 复审绑定最终源码与精确 dev/tracker 交付。纯契约场景不建立公开金融资格。

## 验收标准

- [ ] AC1. 公开显式采集贯穿实际类型化 Control Plane 及外部生产者接缝，验证精确远端账户身份，只使用已有凭据为已保存精确 symbol 读取固定普通账户/佣金 GET。
- [ ] AC2. Rust/schema/TypeScript 对有界来源观察一致，包含三类四费率、原始折扣声明、精确身份、来源/版本、原始收讫、缺失的提供方时间及来源限定状态/质量。
- [ ] AC3. 缺失、畸形、重复、矛盾或未知活动条款不能变成零/完整；义务可见，无浮点比较/舍入或账户费率替代。
- [ ] AC4. 正确披露 BUY BASE / SELL QUOTE 收到资产分支及条件 BNB/回退；开关不选择保证的未来扣费资产，不制造费用/BNB 算术。
- [ ] AC5. Deadline、当前作业/代际/版本保护、共享读取预算、认证/退避、有界观察及单调过期，使失败/迟到结果退役，不更新原始收讫。
- [ ] AC6. 当前 risk/review 捕获在摘要中绑定真实费用来源变化，保留旧捕获，并由已有独立拥有方门禁继续使金融审批/Prepare 不可用；来源有效不产生权威或金融部分状态。
- [ ] AC7. 实际 React 当前/捕获/pre-arm 与键盘1280/768/390 展示完整出处/单位/条件及独立未解决拥有方缺口，刷新/重开历史不变，无溢出或控制台错误。
- [ ] AC8. 公开正常/错误/不完整/矛盾/生命周期 RED/GREEN、当前检查/schema/普通构建/pin/冻结UI 及独立串行 Standards 后 Spec 复审在提交源码通过。配对证据与核对的 dev/tracker 交付只关闭本前置；父/map/完整金融门禁保持 OPEN。

## 本前置票不包含

总费用或折扣 BNB 金额资格、执行级 USDT/BNB 换算及金额上界、费用变化私有订阅、即时认证 preflight、私有流生命周期、真实订单/test order/Arm/consent、新连接/权利/保存来源、原型修复、物理 Sleep/Wake 及 main 合并。这些必需拥有方能力推迟到后续串行票，未从完整 goal 豁免。
